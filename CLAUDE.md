# Fusain

## Description

Atelier de dessin tactile (iPad, mobile, bureau) centré sur le dessin à la trame, en noir et blanc haute
résolution. Il reprend le moteur de Pixel Studio et sert de base à un mode BD : un projet est un document
structuré **pages → cases → calques**, plus des bulles et des textes. Un dessin commencé sur un appareil se
reprend sur un autre. Plus tard : un jeu où l'on dessine (il passerait alors à `game-system`).

- **Catégorie : primaire.** Toutes les fonctionnalités avancées des conventions sont attendues.
- **Cible : mobile et bureau** (tactile d'abord, iPad en tête).
- **Production : https://supershivas.github.io/fusain/** (GitHub Pages, déployé à chaque push sur `main`).
- **Objectif v1.0.0 :** dessiner une page de 4 cases avec trames sur iPad, la reprendre sur un autre appareil, l'exporter en PDF.
- L'IA n'écrit pas d'images : elle n'intervient que par l'import d'un **découpage JSON** (pages, cases, plans,
  dialogues) généré hors de l'app. Format et exemple : `js/portable.js` (`DECOUPAGE_EXEMPLE`).

## Stack

- Vanilla JS en modules ES, sans build ni dépendance (`python3 -m http.server`). Polices Google et icônes Tabler (webfont) par CDN.
- Hébergement : GitHub Pages (`.github/workflows/pages.yml`).
- Données : cache local IndexedDB (copie de travail) + Supabase (projet existant), tables préfixées `fusain_`.
  Schéma, règles RLS et bucket : `supabase/fusain.sql`, à exécuter une fois à la main.
  - `fusain_projects` : une ligne par projet, `data` = description sans pixels.
  - Storage, bucket privé `fusain` : un PNG par calque, `<uid>/<projet>/<calque>.png`.
  - `fusain_library` : une ligne par utilisateur, bibliothèque personnelle (`customBrushes`, `tramaPresets`, `bubbleTemplates`) ; `js/library.js` date chaque élément (`at`) et garde les suppressions (`deleted`, 180 jours), `syncLibrary` (`sync.js`) fusionne élément par élément. Table absente : rien ne casse, les Réglages le signalent.
- Authentification : lien magique par email (Supabase Auth). L'URL du site doit figurer dans les « Redirect URLs » du projet
  Supabase. Pour saisir le code à 6 chiffres (iPad en PWA), le modèle d'email doit contenir `{{ .Token }}`.
- URL et clé anon du projet Supabase : saisies dans Réglages, gardées en `localStorage` (paramètre d'appareil), **jamais commitées**.

## Structure

- `index.html`, `labo.html`, `css/` (`style.css`, `labo.css`, `mobile.css` synchronisé), `sw.js`, `manifest.webmanifest`.
- `js/model.js` — document (projet, page, case, calque, bulle), formats, dispositions. Pixels d'un calque : octets 0 = transparent, 1 = encre, 2 = blanc ; calque `color` : RVBA non prémultiplié, 4 octets par pixel (`bppOf`), propre à sa case. Tout code qui lit `layer.data` doit tenir compte de `bppOf` (historique, `reshape`, copie et fusion de cases, sélection, fusion de calques).
- Types de calques `kind` : `ink`, `tram`, `draft`, `color`. Couleurs : deux couleurs globales `ed.color` / `ed.color2` (préférences), widget `.cw` entre les curseurs de gauche (`colorWidget` : principale = palette, secondaire ou flèche = échange `swapColors`, mini noir / blanc = `resetColors` ; touches X, D, C). Noir et blanc n'ont pas d'autre statut à l'écran ; `ed.ink` est dérivé (`inkOf` : `#000000` → 1, `#FFFFFF` → 2, sinon 3) pour garder les calques 1 bit tant qu'on dessine en noir ou blanc. Fenêtre `color` : sélecteur saturation/luminosité + teinte (`paintPicker`, `pickerDown`), code hex, nuances immédiates (`shadesOf`), harmonies (`harmoniesOf`), palettes nommées du projet (`project.palettes` [{id, name, colors}] + `paletteId`, `projectPalettes` ; l'ancien `colors` devient la première), appui long sur une couleur = retirer, récentes, pipette (bouton : `ed.picking` ; appui long d'un doigt immobile 550 ms sur le dessin : `onLongPress` d'`input.js`, qui annule d'abord le point commencé ; `colorAt` dans `view.js`, voisinage de 3 px d'écran) ; en couleur, chaque outil garde son calque (encre, trame) qui passe en RVBA au premier trait de couleur (`l.rgba`, `toRGBA` annulable, `editor.js`) ; un calque `color` actif reçoit la couleur sans faire barrière au remplissage. Peinture RVBA : `putRGBA` (`raster.js`, vraie opacité, `ctx.seen` : un mélange par pixel et par trait). La couleur ne fait pas barrière au remplissage (`compositeValues`). PNG : `encodePNGRGBA` / `decodePNGRGBA` (`png.js`, lecture exacte sans canevas). Chaque outil vise le calque de sa sorte (`targetLayer` / `peekTarget`, `editor.js`) : encre → `ink` (ou `draft` s'il est actif), trame → `tram`, gomme → calque actif ; un calque manquant est créé. Bulles : `hidden`, `locked`, et `bubblesHidden` par page (non exportées si masquées).
- Réglages de l'outil : uniquement dans la barre **du bas** de la zone de dessin, façon Procreate (`renderOptbar`, `editor-ui.js`), sur **une seule ligne** (défilement horizontal). Pinceau et gomme : **palette du projet** (`paletteControl`, emplacements `data-slot` ; toucher l'actif ouvre `brush`, « + » ouvre `lib-brush`), trame = bouton sans texte qui ouvre la bibliothèque ; **un seul** bouton « Réglages » (icône), à onglets Pinceau / Trame pour le pinceau (`brushPopTab`). La palette de couleurs (`popId` `color`) se ferme au toucher en dehors (`closeColorOutside`, ce toucher ne dessine pas) ou sur sa pastille. Taille et opacité : curseurs verticaux au bord gauche du canevas (`#quick`, `QUICK`), aussi pour formes et masque (taille seule). Appui long sur un curseur = repère aimanté (`toggleTick`, `nearTick` : rayon en pixels selon le pointeur, `SNAP_IN`, décrochage à `SNAP_OUT` × ce rayon), rangé dans `ed.ticks` (par outil) et dans l'emplacement de la palette (`slot.ticks`). Les fenêtres flottantes `#pop` (`popId` : `lib-brush`, `lib-trama`, `brush`, `trama`, `btext`, `bshape`, `btail`) ne se reconstruisent pas si leur HTML n'a pas changé (`syncPop`), pour ne pas perdre un toucher. La gomme utilise le moteur de pinceaux (pinceau propre, valeur 0). Les fenêtres s'ouvrent vers le haut. Plein écran et « masquer le panneau » sont en **pied du volet de droite** (`dock-foot`) ; replié (`.dock.closed`), le volet devient un rail étroit qui garde ces deux boutons (≤ 768 px : bouton dans la barre d'outils). Volet de droite = 2 onglets : **Calques** (calques, bulles, propriétés du calque) et **Page** (pages, notes, cadre, masque, image, copie). Sections `<details>` (`sec()`, état dans `fusain:sections`) ; tout contrôle fermé par défaut doit s'ouvrir avant d'être testé.
- Menus de l'en-tête : `js/menus.js` (Fichier, Édition, Outils, Image, Calque, Page, Affichage ; le menu Outils ouvre la bibliothèque en fenêtre : `libraryModal` ; un seul bouton « Menu » ≤ 768 px). Chaque entrée est une commande de `COMMANDS` dans `editor-ui.js` (`runCommand`) ; ajouter une entrée = une ligne dans `menus()` + une commande.
- Outil **Sélection** (`js/selection.js`, touche `A`) : modes automatique (zone fermée comme le seau), main levée, polygone, rectangle, ellipse ; opérations nouvelle / ajouter / retirer ; tout, inverser, effacer. `ed.sel` = masque d'octets 0/1 en coordonnées de calque, limité au cadre, dans une seule case ; il disparaît en quittant l'outil ou en changeant de page. « Déplacer » (`ed.selMove`) soulève les pixels (tampon par calque, aperçu flottant `ed.selFloat`), les repose au relâchement en **une** entrée d'historique ; sans sélection, il déplace tout le contenu de la case. Portée : tous les calques visibles et déverrouillés, ou le calque actif (`ed.selScope`) ; « copier » laisse l'original. Le déplacement est borné pour qu'aucun pixel ne sorte de l'étendue des calques. Les changements de sélection sont dans l'historique (`setSel` pousse une entrée « Sélection » ; `UndoStack.onSelect` la rétablit, seulement si l'outil Sélection est actif) ; un déplacement garde pixels + sélection dans une seule entrée (`commit({ before, after })`) ; les effacements automatiques (changer d'outil ou de page, sélection implicite) passent `record = false`.
- Ordre des calques : poignée `.grip` à gauche de chaque ligne, glisser-déposer (`gripDown/Move/Up`, `editor-ui.js` ; `moveLayerTo`, annulable) ; la liste est affichée à l'envers (dernier calque = en haut de la pile).
- Calques : `opacity`, `locked`, `color` : nom de palette pour un brouillon, **« #rrggbb » libre pour un calque d'encre ou de trame** (`tintOf`, `raster.js` ; les pixels restent 1-bit, seule la teinte change ; bulles et cadres restent noirs ; le PDF passe en RVB 8 bits seulement si un calque est coloré, sinon 1 bit gris). `compositeRect` mélange en alpha à l'écran ; à l'export (`opts.export`) l'opacité d'un calque d'encre devient un gris tramé Bayer 8 × 8, un brouillon n'est jamais exporté.
- Pinceaux : un pinceau = des paramètres (`BRUSH_DEFAULTS`, `BUILTIN_BRUSHES` dans `raster.js` ; forme, pression, effilage, grain, dispersion, stabilisation). `stampBrush` / `strokeSegment` les rendent ; `tools.js` fournit pression, vitesse, départ effilé et stabilisation. **Pinceau et trame sont un seul outil** (`pencil`) : la trame est un réglage du pinceau (trame `plein` = encre → calque `ink`, montrée comme un cercle noir `.ink-dot` en tête de la bibliothèque et dans la barre, jamais comme une trame « Plein » ; une trame → calque `tram`) ; la gomme partage le moteur. Taille max 50 mm pour le pinceau (`maxSizeMm`), 30 mm sinon. L'ancien outil `texture` n'existe plus (préférences et palettes migrées). **Palette du projet** : `project.brushSet = { pencil, eraser }` (l'ancienne liste `texture` rejoint `pencil`), jusqu'à 10 emplacements (`SLOT_MAX`) par outil, chacun = pinceau complet (`spec`, `sizeMm`, `alpha`, `ticks`, + trame pour `pencil`) ; créée à la première ouverture (`brushSlots`, `editor.js`), synchronisée avec le projet ; tant qu'un emplacement est actif (`ed.slotId`), tout réglage y est rangé (`storeSlot`) ; un pinceau pris dans la bibliothèque y entre (`brushToPalette`). Opacité d'un trait (`ed.alpha`, `paint.alpha`) : seuil Bayer 8 × 8 accroché à la page (`put`, `raster.js`). Pinceaux perso de la bibliothèque (« Mes pinceaux »), taille par pinceau et réglages de trame : `localStorage` (`fusain:prefs`), synchronisés par `fusain_library` ; bibliothèque de trames globale : IndexedDB (`tramaLib`).
- `js/raster.js` — moteur 1-bit : undo **par différences de tuiles 64 px** (`UndoStack`), pinceau, formes, remplissage, composition. Le pot de peinture tolère les contours ouverts (`floodRegion(…, gap)` : encre épaissie, remplissage, regonflé) ; curseur `ed.fillGap` 0–100 (défaut 100 = trous jusqu'à 2,5 mm), dans la barre du bas.
- `js/tramas.js` — tuiles 1-bit (bibliothèque + trames perso par projet), dithering d'image. `dither.js` : matrices de Bayer (venues de Pixel Studio).
- `js/bubbles.js` — bulles vectorielles (aperçu et PDF partagent le code) : forme (ellipse, rectangle à angles réglables, nuage, tracé à main levée), marge intérieure, trait en mm, queue (pointe, flèche, bulles). Les réglages vides retombent sur le modèle du type (`props`). Contour imparfait : bruit déterministe tiré de `b.id` et `b.seed`. **Chaque bulle est liée à une case** (`b.panel`, `linkBubbles`) : supprimer la case supprime ses bulles (rétablies par annuler, `swapPanels`), fusionner les reporte sur la case qui absorbe, copier une case (`copyPanelTo`) ou dupliquer une page les copie, poser une bulle sur une autre case la relie à celle-ci ; elles ne bougent pas quand le cadre change (comme le dessin). Duplication : `duplicateBubble`. **Outil Bulle** : la liste déroulante `lib-bubble` choisit un modèle (`BUBBLE_TEMPLATES` dans `bubbles.js` + modèles de l'auteur `ed.bubbleTemplates`, `saveBubbleTemplate`, `localStorage`) ; un toucher dans une case y pose une bulle de ce modèle (`addTemplateBubble`, `bubbleDown`). La bulle sélectionnée porte une **barre flottante** (`#bfloat`, `placeBubbleUI`, repositionnée par `hooks.afterRender` de `view.js`) : écrire (champ `#bedit` posé sur la bulle), forme (une touche, elle tourne : ellipse → rectangle → nuage → éclair), queue marche / arrêt (la position est retenue), trois **listes déroulantes** Texte / Forme / Queue (réutilisent `bubbleText` / `bubbleShape` / `bubbleTail` et les gestionnaires du volet ; rangées à côté de la bulle, jamais dessus ; l'onglet Texte n'a que le texte, le modèle de bulle est dans Forme), copie, corbeille. Nouvelles bulles : majuscules décochées, police Architects Daughter. En taille auto (`padOf`, `innerFactor`), la marge intérieure a un plancher (trait, imperfections, corps) et le cadre du texte est le rectangle inscrit dans la forme : le texte ne touche jamais le trait. La courbure de la queue (`tailBend`) s'inverse quand sa base est à droite de sa pointe (queue en miroir). Forme `cloud` (`lobes` 0 = auto selon la taille, jamais selon le trait ; `bulge`, `cloudSoft`, `wobble` ; `cloudPoints` sert au tracé ET à l'accroche de la queue) ; forme `eclair` (cri / explosion : `spikes`, `depth`, `wobble`, `valleyRound`, `tipRound` en courbes, `traceEclair`) et type `cri`. Les listes de pinceaux, gommes (groupe « Mes gommes »), trames et bulles ont chacune un bouton « Enregistrer… ». Outil Cases : un bouton « Fusionner » (`mergeButtons`, `view.js`) au centre de chaque case voisine absorbable. Rotation `b.rot` (degrés autour du centre ; la pointe de la queue reste fixe sur la page ; `bubbleToPage` / `bubbleToLocal`, poignée de rotation aimantée tous les 15°) ; `b.sameStroke` (trait = celui du cadre de sa case), `b.noFrame` (avec `clip` : la bulle efface le trait du cadre là où elle le touche, `drawPageBubble`), `applyBubbleLines` (copie ces traits sur toutes les bulles du projet) ; `b.clip` rogne la bulle au cadre de sa case (`drawPageBubble`) ; corps du texte jusqu'à 200 pt ; alignement du texte `align` (left / center / right) et `valign` (top / middle / bottom) dans le modèle du type (`BASE`), réglés dans l'onglet Texte (`talign` / `tvalign`), le bloc s'aligne dans le rectangle inscrit (`drawBubble`) ; l'alignement vertical ne se voit qu'avec « Taille auto » décoché. `js/fonts.js` : 26 polices Google (feuille de `index.html`) + polices importées (IndexedDB, par appareil) ; toute police doit être chargée (`loadFont`) avant un rendu sur canevas. `js/export.js` — rendu de page, PNG, PDF écrit à la main.
- **Case = cadre visible (`x,y,w,h`) + étendue des calques (`ex,ey,ew,eh`)** : les calques couvrent au moins le cadre et ne rétrécissent jamais, donc réduire une case ne coupe rien (`reshape`, `editor.js`). Coordonnées de calque = page − `ex,ey` ; on ne dessine que dans le cadre (`ctx.clip`) ; le remplissage voit hors cadre comme de l'encre. Fusion : `mergeCandidates` / `mergePanels` ; suppression : `deletePanel`.
- Réglages par outil : `TOOL_DEFAULTS` / `storeToolSettings` / `applyToolSettings` (`editor.js`), rangés dans `localStorage` (`fusain:prefs`) avec le dernier style de chaque type de bulle (`bubbleDefaults`). Les tailles se règlent en mm (`sizeMm`), `ed.size` en est la valeur en pixels.
- Gouttières : `gutterHandles` / `resizeGutter` (`editor.js`) ; Ajout de case : la case active porte un « + » sur chacun de ses 4 bords (`edgePluses`, `view.js`) ; un toucher montre la future case en pointillés (`ed.addPreview`) ; sa poignée sur la ligne pointillée règle la part (20–80 %, aimant à 25/33/50/67/75 : `ed.addRatio`, `ratioMove`) et une pilule ✕ ✓ au centre de la nouvelle case abandonne ou ajoute (`previewControls`, Entrée / Échap au clavier ; gouttières et autres « + » masqués pendant l'aperçu) (`splitRects` / `addCaseAt` / `confirmAdd`, `editor.js`) : elle prend la place de la case coupée, la page ne grandit pas et rien n'entre dans la marge. Les gouttières ne portent plus de « + ». Déplacer une gouttière affiche en direct le nouveau cadre et les dimensions en mm des cases touchées (`gutterPreview`). `splitRects` ramène la part demandée dans ce que la taille minimale (10 % de la page) permet, et une nouvelle prévisualisation repart à 50 %. Elles regroupent les cases qui bordent une même gouttière ; `reshape` garde le dessin à sa place sur la page. Copie de case : `copyPanelTo`. Appui long sur un pinceau (palette ou « Mes pinceaux ») : retiré, avec Annuler (`attachHold`, `editor-ui.js`).
- Gestes (`input.js`) : deux doigts zooment **et tournent la page** (`view.r`, rotation comptée au-delà de 8°, aimant tous les 45° à ±5° ; `toPage` / `toScreen` en tiennent compte, jamais `view.ox/oy/s` seuls ; menu Image : « Tourner de 90° », « Remettre droite », `0` ajuste et redresse) ; un toucher en mode déplacement (outil main, ou doigt quand le stylet est en usage) change de case sans dessiner ; deux doigts zooment, tape à deux = annuler, tape à trois = rétablir, trois doigts qui frottent (≥ 4 allers-retours) ou tournent vident le calque actif. Dès que trois doigts bougent, le geste n'est plus un « tape ». Rejet de la paume (`input.js`, réglage `ed.palm` : fort 1,6 s / normal 0,7 s / off) : un doigt **isolé** posé pendant ou juste après un appui de stylet est marqué `palm` (il ne dessine ni ne déplace la vue, et ne compte pas dans les gestes) ; un second doigt rend les deux réels, donc zoom / annuler / rétablir restent libres. Ni le survol ni la taille du contact ne comptent (Safari ne les rapporte pas de façon fiable) ; un « stylet posé » sans relevé expire après 3 s. Stylet : bouton du flanc = bascule plume ↔ gomme (le double tape du bout a été retiré : il changeait l'outil par erreur) ; bout gomme (`buttons & 32`) = gomme le temps du trait. Le double tape du flanc de l'Apple Pencil n'est pas exposé aux pages web. Pression : `pressureOf` (`tools.js`) applique la courbe `ed.pressureGamma` ; la pression d'un stylet n'est jamais remplacée par 0,5.
- **Mode case** (`ed.focus`, booléen ; la case ouverte = `ed.panelId`) : `viewBounds` / `focusPanel` (`view.js`) bornent `fit`, `clampView` et le zoom à la case ; le rendu ne montre qu'elle et les bulles **liées** à elle (`b.panel`, rognées), seules touchables. Les bulles appartiennent à leur case (`linkBubbles`) : le volet ne liste que celles de la case ouverte, et `selectBubble` ouvre la case de la bulle. `panelAt` (`tools.js`) ignore les autres cases. Entrée : double toucher d'un doigt qui déplace la vue ou de la main (`onDoubleTap`, `input.js`), bouton de la barre de zoom, Entrée, menu Image ; sortie : idem, ou outil Taille des cases, ou changement de page. `setFocus` / `stepCase` dans `editor-ui.js`.
- `js/view.js` (rendu et zoom), `input.js` (Pointer Events, rejet de la paume, pincer), `tools.js` (outils au pointeur), `editor.js` (état et actions annulables).
- `js/shell.js` — plein écran (Safari iPad seulement, pas iPhone), détection iOS / installé, garde-fous contre la sélection, le menu de pression longue, le zoom de page et le double toucher (avec le CSS de `style.css`). Les champs de saisie gardent `user-select: text`, sinon Safari ne les laisse plus taper.
- `js/store.js` (IndexedDB, PNG 2 bits via `png.js`), `sync.js` (Supabase par `fetch`), `portable.js` (export/import JSON, découpage).
- `js/home.js`, `editor-ui.js`, `menus.js`, `settings.js`, `ui-core.js`, `toast.js`, `main.js` (routage `#/p/<id>`), `app-update.js` (copié du design system).

## Exceptions aux conventions

- **Temps réel** : entre onglets par `BroadcastChannel` ; entre appareils par sondage (au retour au premier plan et toutes les 60 s),
  pas par Supabase Realtime.
- **Atelier** (section 8 quater) : non créé, il n'a pas été demandé (l'app est elle-même un atelier). **Labo** : `labo.html`, sujets Trames et Bulles (dont « Outil Bulle » : 5 bancs d'essai interactifs de l'ergonomie, `bubbleLab` dans `labo.js`).
- **Parité visuelle** : pas de barre latérale comme Idée et Source ; en-tête, boutons, modales et toasts suivent les tokens.
- Les trames personnalisées sont stockées **par projet** (dans `data.tramas`), pas dans une bibliothèque globale.

## Pièges connus

- Seule la **page ouverte** a ses pixels en mémoire (`loadPage` / `unloadPage`). Ne jamais lire `layer.data` d'une page non chargée ;
  l'historique est vidé à chaque changement de page.
- `UndoStack.touch()` doit précéder toute écriture dans un calque (il capture la tuile d'origine et marque le calque `dirty`).
  Après un changement de pixels, appeler `invalidate(panel, rect)` (vue) et `markChanged()` (enregistrement).
- Écrire l'enregistrement projet avec `updateRecord` (une transaction) : l'éditeur et la synchronisation y écrivent tous deux.
- Une page A4 à 300 dpi fait 2480 × 3508 px (8,7 Mpx) : sous la limite de 16 Mpx des canevas de Safari. Ne pas dépasser 300 dpi.
- L'encodage PNG par `canvas.toBlob` est très lent sur grand format : `png.js` écrit le PNG indexé lui-même (`CompressionStream`, repli sur le canevas).
- Pas de `hover` hors `@media (hover: hover)` (iOS prend le premier toucher pour un survol).
- Tests faits avec Playwright hors dépôt (aucun `package.json`) : dessin souris/stylet/tactile, undo, sync contre un faux Supabase, PDF vérifié avec `pdftoppm`.
